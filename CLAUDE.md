# Yunoly Admin (admin.saurroemanuele.com)

- Before editing, always `git pull` / start from the latest `origin/main`: more than one session works on this repo, and editing a stale copy of `app.js` silently removes other sections.
- Never rewrite `app.js` wholesale; make targeted edits and keep every existing view (`VIEW_PERM`, `load()`, `render()`, `SUB`, nav buttons in `index.html`).
- Owner-only "Personal brand" section (view `brand`, perm `brand_owner`, RPC `brand_funnel` / `brand_lead_delete`): leads and funnel of saurroemanuele.com. Must stay.
- Bump the `?v=` cache numbers in `index.html` when changing `app.js` / `app.css` / `studio.js` / `studio.css` / `yunoly.css`.
- Owner-only "Lead dal sito" section (view `leads`, perm `yunoly_leads`, in `studio.js`): requests from the yunoly.com forms (investitore, founder, creator, contatto). Table `admin_api.yunoly_leads`, written only by `public.submit_yunoly_lead(p)` (rate limited via `webclip_hit`); routes `yunoly_leads`, `yunoly_lead_save`, `yunoly_lead_delete` (audited) in `admin_call`.

## Company layer (studio.js + studio.css)
- The company name lives only in `COMPANY` at the top of `app.js` ("Yunoly", the studio; NoonFrame and CaliCam are its apps). Nav wordmark, login screen and page title read it; the tab icon is the static `favicon.png` (Yunoly logo).
- App icons: `APP_ICON` in `studio.js` maps the app id to `apps/<name>.png` (the app id `strikt` is CaliCam: only the name changed, ids and metrics stay). Apps without an icon show their initial.
- `studio.js` holds the company sections and registers them in `EXT` (defined in `app.js`): Panoramica (view `home`, the landing view), one page per portfolio app (view `app:<id>`, perm `launch`), Pagine satellite (view `satellite`). Keep the `EXT` hooks in `allowed()`, `go()`, `load()`, `render()` and `enter()`; `gate()` starts on `DOMContentLoaded` so `studio.js` is loaded first.
- Everything in `studio.js` stays inside its IIFE (no new globals: they would clash with `app.js` names).
- Brand: Yunoly light theme like yunoly.com, in `yunoly.css` (loaded last, overrides the dark variables of `app.css` / `studio.css`): white, ink #0b0f19, blue #1e5ef5, Plus Jakarta Sans self-hosted in `/fonts` (CSP has `font-src 'self'`). The nav/login mark is `yunoly-logo.png`; `logo.png` stays the NoonFrame app logo. New hardcoded colours must work on white. App colours come from the 8 chart-safe colours in `APP_COLORS`.
- Database (Supabase `jhoidpugjjvvkjccyrxg`): `admin_api.apps`, `app_metrics`, `sat_pages`, `sat_accounts`, `sat_weeks`; routes `studio`, `apps`, `app`, `app_save` (perm `apps`), `sat`, `sat_save`, `sat_secret` (perm `sat_access`, owner-only to grant) in `admin_call`. Account passwords and private notes are only in Supabase Vault and only `sat_secret` returns them; every `sat_secret` call is written to the audit log.
- Partner apps (e.g. CaliCam, id `strikt`) send numbers to `public.metrics_push(token, data)` with a key created on their app page (only a SHA-256 hash is stored).

## Security (keep these when changing the panel or the database)
- Only `public.admin_call` (team + Google account + aal2 + permission per route), the app's own `app_*` / `web_*` functions (all scoped to `auth.uid()`) and the public form endpoints (`submit_yunoly_lead`, `submit_brand_lead`, `track_brand_event`, `metrics_push`, `mail_unsubscribe`) are callable from outside. `anon` / `authenticated` have no table privileges in `public` and no access to `admin_api`: never add grants or permissive policies, add a security definer function instead.
- Team membership = email in `admin_api.team` AND a Google identity with that email (`admin_api.me()`). Triggers `guard_team_email` (on `auth.users`) and `guard_team_member` (on `admin_api.team`) stop a non-Google account from taking a team email. Admin edge functions (`admin-keys`, `admin-finance`, `admin-strikt`, `affiliate`) check the team by email, so these triggers protect them too.
- Rate limits on public forms use `admin_api.client_key(prefix)`: Cloudflare's `cf-connecting-ip` (the first `x-forwarded-for` value can be forged by the client), stored only as an HMAC with the `ip_salt` setting, never the raw IP.
- Owner-only permissions (`OWNER_ONLY` in `app.js`, the owner list in `team_save`) appear in the member window under "Email ai creator", "Founder" and "Dati riservati" (`yunoly_leads`, `sat_access`). A new owner-only permission must be added in all three places.
- User-written text is always rendered with `el()` (text nodes), links only through `extUrl()` (http/https). Never use `innerHTML` with data from the database.
